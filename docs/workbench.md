# タスクとコード編集

Experimentの下にTaskを保存し、そのTaskから通常実行やテストを起動します。Taskにはコード版、モデル版、入力データセット版、パラメータ、Compute、GPUを指定します。コードを編集した後も、過去のJobで使った内容を確認できます。

## サンプルから実行する

1. **Compute**で実行先を追加します。SSH接続先では、workerに秘密鍵とknown_hostsを用意します。開発モードのCPU実行はlocal executorを使います。
2. **コード**でコードを作成し、版を登録します。サンプルを選ぶとファイルと通常・テストのコマンドを読み込めます。
3. Monaco Editorでファイルを編集し、新しい版として保存します。ファイルの追加・削除も行えます。
4. **タスク**で実験とコード版を選び、Computeとパラメータを保存します。
5. **テスト実行**で動作を確認してから通常実行します。Runからメトリクス、ログ、終了状態、Artifactsを確認できます。

workerの起動方法は[worker手順](worker.md)を参照してください。Computeの登録後、対応するworkerが起動しているとJobが実行されます。

## リポジトリと単体コードを選ぶ

GitはURLと完全なcommit hashを指定し、ファイルを読み込みます。学習コードと推論コードを同じリポジトリに置く場合も、コマンドを変えたCodeVersionをそれぞれ登録できます。推論コードだけ別リポジトリを指定することもできます。

Gitの編集は、固定commitに変更ファイルと削除パスを重ねて保存します。元のリポジトリへのpushは行いません。読み込まれなかったバイナリや大きいファイルは元のcommitに残り、実行時に取得します。

単体コードはファイルを直接保存します。ZIP/TARのArtifactや、コンテナ内のコードも選べます。Docker・Singularity・Apptainerの登録方法は[コンテナ手順](containers-automation.md)を参照してください。

## Jobごとの実行コードを確認する

コード版は不変です。編集して保存すると新しい版になります。Taskの保存時はrevisionが増え、起動時に指定したrevisionとコード版をRunへ記録します。他の画面でTaskが更新されていた場合は409を返し、最新の設定を確認してから実行します。

Runの`executionSnapshot`には、選んだコード版・ソース・Runtime・コマンド・依存関係・環境設定を保存します。テストではコード版の`testEntrypoint`、通常実行では`entrypoint`を使います。起動後の編集や別のTask版は、この内容を変更しません。

workerは実行前のソースをZIPとmanifestに保存し、RunのArtifactsへ送ります。空フォルダと実行権限も保存し、失敗したテストでも送ります。manifestからRun・Job・CodeVersionのID、Git commit、ファイルのSHA-256を確認できます。コンテナ内のコードだけを使う場合は、固定image/SIF情報をmanifestに残します。

Taskの実行履歴は最新50件から表示します。「古い実行」で続きを開き、「最新の実行」で先頭に戻れます。実行内容の全文はRun詳細から確認します。

再実行は前のコード版・実行モード・Task revision・パラメータを引き継いだ新しいRun/Jobになります。編集したコードを試すときは、Taskのコード版を更新して新しく起動します。

## 学習が成功したらモデルを登録する

training/finetuningのTaskでは「成功時に出力モデルを登録」を設定できます。登録先は既存のModelを選ぶか、新しいModelの名前と系列を入力します。系列はTaskのコード版が対応する系列から選びます。Artifactパスには学習コードが保存した重みファイルを指定します。SDKを使わないコードは`MMT_OUTPUTS_DIR`へ書いたファイルが`container/<path>`として保存されます（[worker手順](worker.md)）。

| 状況 | 結果 |
|---|---|
| Runがfinished | 版を登録し、自動推論・評価のruleがあれば起動する。版名は自動採番（版名テンプレートを指定した場合はその名前） |
| 学習コードが同じModelへ登録済み | Task側は登録しない（skipped）。版も下流の実行も1つ |
| Artifactが無い・権限が無い | 失敗として理由を記録する。Runはfinishedのまま |
| failed/canceled・テスト実行 | 登録しない |

設定は起動時にRunへ複写します。起動後にTaskを編集しても、そのRunの登録先は変わりません。結果はRun詳細の出力モデルで確認します。

## Computeとpluginの設定を変える

全体管理者はComputeの追加・設定編集・有効切替を行えます。Jobが参照している接続先やGPUを変更するときは、そのJobが終わってから保存します。無効化は新しい実行を止め、実行中のJobはworkerが引き続き管理します。

pluginも全体管理者が登録・編集・有効切替を行います。Mado presetを使い、別リポジトリで動かすHTTP serviceのURLと認証用環境変数名を指定します。接続確認でmanifestを読み込み、データセット参照、metrics、lineageを使います。設定変更後は再度接続を確認します。

pluginの起動・認証設定は[plugin仕様](plugins.md)を参照してください。
