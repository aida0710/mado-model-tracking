# 評価の比較と昇格

![昇格policyと判定履歴](/images/models-promotion-policies.png)

新しい版の評価結果を、`production`が指す版（基準版）の評価と並べて比べられます。昇格policyを作ると、評価Runが終わった時点で合否を判定し、合格した版へAliasを自動で切り替えることもできます。

## こんなときに向いています

- 新しい版が今の本番の版より良くなったかを、同じ評価データ・同じ評価コードで比べたい
- 「WERが5%以上下がったら合格」のような基準を決めて、判定を自動にしたい
- 合格した版だけを`production`にしたい。不合格の版を本番にするときは理由を残したい
- 誰が、いつ、どの判定を根拠に本番の版を切り替えたかを後から確かめたい

## 評価結果を比べる

![版の詳細画面の評価結果](/images/models-version-evaluation.png)

版の詳細画面の［評価結果］に、その版の評価Runの指標と、基準版との比較を表示します。

- ［指標の集約］: 成功した評価Runのうち最も新しいものの値と、基準版の値、差の符号です。
- ［評価Run］: この版の評価Runの一覧です。自動評価のRunには、どのルールで動いたかを表示します。
- ［基準版との評価比較］: ［基準にする版］を選ぶと、指標ごとに候補・基準・差・相対差と、比較に使った正解セットと評価コード版を表示します。

差は「候補−基準」、相対差は「差÷|基準|」です。指標が大きいほど良いのか小さいほど良いのかは、比較の画面では判断しません。判断の方向は昇格policyで決めます。

### 比べられる評価Run

候補版と基準版の評価Runは、次がすべて一致するときだけ比べます。

1. 同じProjectで、実行種別が評価、状態が完了のRun
2. 正解セット（評価に使った入力データセット版）が同じ
3. 評価コード版が同じ

連鎖した評価Runの入力には、推論の出力も含まれます。推論の出力は版ごとに違うため、比較の条件には含めず、ルールに固定した正解セットだけで判定します。

一致する評価Runが無いときは、エラーにせず次のように表示します。

| 表示 | 対処 |
| --- | --- |
| 「基準aliasが設定されていないため比較できません。」 | 基準にする版にAliasを設定します |
| 「この版の完了した評価Runがありません。」 | この版に評価のルールを適用します |
| 「基準版に、同じ正解セットと評価コード版で完了した評価Runがありません。」 | 基準版にも同じ評価のルールを[適用](/models/automation#apply-a-rule-to-existing-versions)します |

基準のAliasが候補の版自身を指しているときは、直前に登録された版を基準にします。

条件をそろえるには、評価を[自動実行ルール](/models/automation)で回すのが確実です。ルールは評価コード版と入力データセット版を固定して保存するため、どの版にも同じ条件の評価Runができます。

## 昇格policyを作る

昇格policyは「このモデルの版を、この評価ルールの結果で合否判定する」設定です。作れるのはProject adminです。

1. Modelsの［昇格policy］を開き、［昇格policyを作成］を押します。
2. 次の項目を入力して保存します。

| 項目 | 内容 |
| --- | --- |
| 名前 | 例:`production への昇格基準` |
| 対象モデル | 判定するモデル |
| 対象alias | 合格した版を指すAlias。例:`production` |
| 基準alias | 比べる相手の版を指すAlias。既定は`production` |
| 評価ルール | 対象モデルの系列を扱う、有効な評価のルール。判定にはこのルールが作った評価Runだけを使います |
| 合否基準 | 1〜50件。すべて満たすと合格です |
| 基準aliasが未設定のとき | ［合格にする（初回の登録）］か［不合格にする］ |
| 合格したら対象aliasを自動で切り替える | 既定は切り替えません |

3. 一覧に追加されたpolicyの［状態］が［有効］になっていることを確かめます。

policyも、作成した後は有効と無効しか変えられません。基準を変えるときは新しいpolicyを作り、古いpolicyを無効にします。過去の判定は、作ったときの基準のまま読めます。

### 合否基準の書き方

基準ごとに［メトリクス］［良い方向］［比べる値］［閾値］を指定します。

| 比べる値 | 閾値と比べるもの |
| --- | --- |
| 候補の値 | 候補版の値そのもの |
| 基準との差 | 候補−基準 |
| 基準との相対差 | (候補−基準)÷\|基準\|。比率で入力します（0.05は5%） |

［良い方向］が［大きいほど良い］なら「比べる値≧閾値」、［小さいほど良い］なら「比べる値≦閾値」で合格です。閾値ちょうどは合格です。

| 基準の例 | メトリクス | 良い方向 | 比べる値 | 閾値 |
| --- | --- | --- | --- | --- |
| accuracyが0.8以上 | `accuracy` | 大きいほど良い | 候補の値 | `0.8` |
| accuracyが基準版から下がらない | `accuracy` | 大きいほど良い | 基準との差 | `0` |
| WERが基準版より5%以上下がる | `wer` | 小さいほど良い | 基準との相対差 | `-0.05` |

値が小さいほど良い指標で改善を求めるときは、閾値を負の数にします。

### 判定の結果

評価のルールが作った評価Runが完了すると、その場で判定して［判定履歴］に残します。

| 判定 | 意味 |
| --- | --- |
| 合格 | すべての基準を満たしました |
| 不合格 | 満たさない基準が1つ以上あります。値が無い、NaN・無限大の基準も不合格です |
| 判定不能 | 基準版に同じルールの評価が無いなど、判定に必要な評価がありません |
| 判定せず | policyの実行ユーザーの権限が無くなった、判定中にエラーが起きた |

- 基準のAliasがまだ無い初回は、［基準aliasが未設定のとき］の設定に従います。［合格にする（初回の登録）］なら差・相対差の基準を合格扱いにし、「初回合格（基準なし）」と表示します。［候補の値］の基準は初回でも判定します。
- 人が作った評価Runと、別のルールが作った評価Runは判定しません。評価Runは誰でも作れるため、判定の対象をルールの自動実行に限っています。
- 失敗・中止した評価Runは判定しません。

判定履歴は追記だけで、変更・削除はできません。Project adminが［再判定］を押すと、今の基準のAliasで判定し直した行を追加します。基準版の評価を後から用意して「判定不能」を解消するときに使います。

## 合格したら自動で昇格する

［合格したら対象aliasを自動で切り替える］を選んだpolicyは、評価Runの終了時の判定が合格なら、対象のAliasを候補版へ切り替えます。

- 判定の途中で誰かが手でAliasを変えていたら、その変更を上書きしません。版の詳細画面の［昇格の判定］に「判定中に基準aliasが変わったため、自動昇格しませんでした。」と表示します。
- 候補版がすでに対象のAliasなら、何もしません。
- ［再判定］はAliasを動かしません。再判定の結果で切り替えるときは、人が昇格のダイアログで判定を根拠に指定します。
- 自動で切り替えたことは、Aliasの履歴に経路「昇格policy」と、policy名・基準ごとの値の要約として残ります。

### policyの所有者を移す

policyは、実行ユーザーの権限で判定し、自動昇格もそのユーザーの操作として記録します。実行ユーザーは最初はpolicyを作った人です。その人がProject adminでなくなると、判定が「判定せず」になります。長く使うpolicyは、一覧の［所有者を移管］で、roleがadminのService Accountへ移しておきます。

## 手で昇格する

版の詳細画面の［昇格の判定］で［昇格］を押すか、Modelsの［Aliasを設定］を押すと、昇格のダイアログが開きます。

1. ［Alias］と［版］を指定します。
2. ［根拠となる判定］で、この版の合格判定を選びます。保護Aliasで合格判定が必須の場合は、ここで選ばないと保存できません。
3. 合格判定を選ばない場合や、不合格の版を指定する場合は、［理由］を入力します。
4. ［保存］を押し、Aliasの一覧と［Aliasの履歴］で切り替わったことを確かめます。

判定のあとに基準のAliasが別の版へ移った場合、その判定は今の基準版と比べていないため、根拠の候補に自動では選びません。

## 保護Aliasを設定する {#protect-an-alias}

`production`のような重要なAliasは、手で変えられる人と条件を絞れます。保護の追加・変更・解除はProject adminだけが行えます。

1. Modelsの［保護alias］を開き、［保護aliasを追加］を押します。
2. ［対象］（プロジェクト全体か、特定のモデル）、Alias名、［変更に必要なrole］、［合格判定を必須にする］を指定して保存します。

| 設定 | 手で変えられる人と条件 |
| --- | --- |
| adminのみ | Project admin（全体管理者を含む）。合格判定か理由が必要 |
| editor以上、合格判定を必須にする | editor以上で、この版のこのAliasへの合格判定を根拠に指定したときだけ |
| editor以上、合格判定は不要 | editor以上。合格判定か理由が必要 |
| adminのみ、合格判定を必須にする | Project adminが合格判定を指定したときだけ |

- プロジェクト全体とモデルの両方に設定があるときは、それぞれの厳しい方を使います。モデルの設定で緩めることはできません。
- 保護Aliasは、MLflow 3互換APIからは変更できません（`set_registered_model_alias`などは`PERMISSION_DENIED`になります）。理由も判定も渡せないためです。画面か独自APIで変更してください。
- 合格判定が必須の保護を解除できるのはProject adminだけです。

## 履歴

| 何の履歴か | 見る場所 |
| --- | --- |
| Aliasをいつ、誰が、どの版へ変えたか | Modelsの［Aliasの履歴］ |
| どの版がどの基準で合格・不合格になったか | ［昇格policy］の［判定履歴］、版の詳細画面の［この版の昇格判定］ |
| policyと保護Aliasの作成・変更 | 監査ログ（[監査ログ](/admin/audit)） |

どの履歴も追記だけで、変更・削除はできません。

## 評価結果のファイルを書く {#write-an-evaluation-results-file}

評価Runがサンプルごとの結果をjsonlのArtifactとして保存すると、RunのArtifactsタブで表として確認できます。音声の再生、正解と推論の文字単位の差分、scoreでの並べ替えができます。

```jsonl
{"audio": "eval/audio/0001.wav", "reference": "今日は晴れです", "prediction": "今日は雨です", "score": 0.29}
{"audio": "mmt-artifact://runs/<推論RunのID>/container/outputs/0002.wav", "reference": "こんにちは", "prediction": "こんにちは", "score": 0}
```

- 列名は`audio`、`reference`、`prediction`、`score`です。`audio`列か、`reference`と`prediction`の両方がある表を評価結果として表示します。
- `audio`の相対パスは、表を保存したRunのArtifactとして解決します。上流の推論Runの音声は、`mmt-artifact://runs/<推論RunのID>/<保存パス>`で指します。同じProjectのRunだけを解決します。
- ヘッダー行付きのCSVも読めます。読めない行は補完せず、行番号と理由を表示します。

音声の表示は[音声ビューア](/data/audio)を参照してください。
